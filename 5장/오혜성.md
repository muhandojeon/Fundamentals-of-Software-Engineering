# 자동화 테스트: 좋은 소프트웨어를 만드는 최고의 습관
* 품질은 단발성 행위가 아니라 습관이다

## 테스트하지 말아야 할 것

* 테스트가 외부 서비스에 의존하지 않게 작성하자. 단위 테스트에는 모의 객체를, 통합 테스트에는 테스트 대역을 대신 사용하자

> 테스트 대역이 뭔지 검색을 좀 해봤는데, 일반적으로 말하는 '모킹', '스텁' 과 같은 내용인듯
> (대역 배우할 때의 대역)
>
> vi.mock, vi.fn, msw 같은 ..

## 테스트 작성

- 테스트 주도 방식과 테스트 후행 방식
> EDD (Evaluation)이 흥하는 것처럼 요즘 시대에는 TDD를 하지 않을 이유가 없다 생각
> 테스트 작성 비용이 0에 가깝기도 하고
> 에이전트의 작업자 편향을 줄일 수도 있고 (테스트 작성자와 구현자를 나눈다던가)
> > https://www.anthropic.com/engineering/harness-design-long-running-apps
> 그 과정에서 좋은 테스트와 소프트웨어가 무엇인지 알 수 있게 하는게 중요하지 않을까 싶음
> 
> 여러 에이전트 프레임워크? 들이하는 것처럼 'tdd'라는 것을 키워드 맵핑해두면 편하더라구요

## 정리

- 건강한 생활방식을 유지하는 것과 마찬가지로, 좋은 소프트웨어를 만드는 일은 긍정적인 습관을 만들고 꾸준히 건강한 선택을 하는 과정임을 명심하자 
- 버그를 다룰 때, 재현하는 테스트를 먼저 작성하자. (그물 좁히기)
