# 5장 자동 테스트: 좋은 소프트웨어를 만드는 최고의 습관

테스트의 장점

1. 문서 역할
2. 개선이 필요한 부분을 빨리 발견 가능(ex. 메서드가 너무 많은 일을 하고 있음) → 더 나은 설계로 이어짐
3. 테스트가 문제를 잡아줄 거라는 믿음을 가지고 코드 리팩터링 가능
4. 시스템 동작에 대한 더 나은 이해
5. 버그를 빨리 잡아내어 수정 비용과 노력 절감
6. 수동 테스트와 다르게 여러 사람에게 일관된 결과를 제공

> 전 3,5번이 큰 장점으로 느껴져요

자동 테스트의 3가지 유형

- **단위 테스트**(unit test): 개별 구성요소 자체가 올바르게 작동하는지 확인
- **통합 테스트**(integration test): 여러 구성요소가 하나의 결합된 단위로서 어떻게 연결되어 작동하는지 검증
- **종단 간 테스트**(E2E test): 가장 앞단의 사용자 인터페이스에서 시작해 백엔드 시스템까지 애플리케이션 전체를 다룸

> 아무래도 단위 테스트가 가장 만만하네요 ㅎㅎ..  
> E2E 테스트 작성할 때는 [Playwright Test Agents](https://playwright.dev/docs/test-agents) 사용하는데 괜찮더라구요  
> planner가 테스트 계획 짜기 → generator가 계획을 테스트 코드로 옮기기 → healer가 실패한 테스트 고치기, 이렇게 이어지는 흐름이에요

테스트를 작성하는 방식

- 테스트 선행 방식: 실패하는 테스트를 먼저 작성하고, 테스트를 통과하는 최소한의 코드를 구현한 뒤, 코드를 개선(리팩터링)한다.
- 테스트 후행 방식: 기능을 구현한 뒤에 테스트 작성

> 먼저 작성하든 나중에 작성하든 필요한 로직에 테스트 코드가 있으면 된다고 생각합니다

경력을 쌓는 과정에서 테스트가 습관이 되도록 노력하자.
