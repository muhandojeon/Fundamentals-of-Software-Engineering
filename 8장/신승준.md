# 8장 다양한 데이터 기술을 적절하게 사용하는 방법

## 대규모 데이터셋

대규모 데이터셋을 다룰 때는 다음을 고려하자.

- 여러 스레드가 동시에 데이터에 접근할 때 잠금, 원자적 연산 또는 불변 데이터 구조를 사용해 적절한 동시성 제어를 구현하고 데이터 경쟁을 막자.

> 멘토링 예약 시스템이 제품에 있었는데, 동시성 제어도 안되고 조금만 몰려도 터지면서 아주 그냥 불만이 넘쳤던 기억이 납니다.
> lock과 원자적 연산으로 개선했던 기억이 나네요.

## 데이터베이스 연결과 트랜잭션

- 트랜잭션: 트랜잭션은 일부만 반영되는 변경이 적용되지 않도록 해서 데이터 무결성을 유지한다.

> 결제에 트랜잭션이 적용되어 있지 않아서, 결제는 되었는데 데이터는 생성되지 않았던 무서운 사례를 겪었었습니다...

## 캐시를 사용한 성능 최적화

- 조회 후 적재: cache-miss 시 데이터베이스에서 데이터 조회 후 캐시에 저장. cache-hit 시 캐시로부터 데이터 조회

> 랭킹 대시보드에 쓰기 좋은 전략같습니다.

- 지연 기록: 데이터를 캐시에 즉시 쓰고 데이터베이스는 비동기로 업데이트. 캐시 기록 작업 실패 시 데이터 손실 위험 존재

> hackle이라는 로깅 sdk가 생각나네요.
> 이전에 파본 적이 있는데 로깅의 경우 너무 많은 http 요청이 단 시간에 발생할 수 있으니 배칭 전송을 하더라구요.
> 그래서 성능을 개선할 수 있는 반면, 브라우저나 컴퓨터 강제 종료 시에는 유실될 수 있습니다.
> 모아뒀다가 한 번에 전송해서 성능을 개선하는 반면, 데이터는 유실될 수 있으니 지연 기록으로 볼 수 있을 것 같습니다.
