# 10장 운영 환경: 코드가 살아야 하는 낯선 환경

잘못될 수 있는 것은 반드시 잘못된다 - 머피의 법칙

## 예측 불가능한 사용자

> 실제로 사용자 PC의 시스템 시간을 임의로 변경해 이미 종료된 프로모션에서 구매를 시도한 사례가 있었습니다    
코드를 확인해보니 클라이언트에서 Date를 통해 얻은 사용자 로컬 시간을 기준으로 프로모션 종료 여부를 판단하고 있었고, 이를 서버 기준으로 검증하도록 수정했던 경험이 생각나네요   


## 운영 시스템 모니터링과 유지보수

> 데이터독을 사용하고 있지만, 프론트에서는 가끔 로그를 통해 어떤 4xx 에러가 발생했는지 확인하거나, 전역 에러 바운더리로 throw된 에러나 React 하이드레이션 오류가 발생했을 때 이를 확인하고 수정하는 정도인 것 같습니다..  
> RUM을 가끔 보는 것 외에는 모니터링을 적극적으로 활용하고 있지는 않은 것 같네요
> 
> 다들 모니터링 서비스를 사용하신다면 프론트엔드에서는 어떤 지표나 에러를 어떻게 모니터링하고 계신지 궁금합니다
