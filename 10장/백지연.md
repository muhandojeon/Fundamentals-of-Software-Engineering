# 10장 운영 환경: 코드가 살아야 하는 낯선 환경

개발 환경과 운영 환경 사이의 차이를 이해하고, 그 간격을 효과적으로 메우는 개발자가 되어야 한다.

개발과 운영의 차이는 주로 두 가지 형태로 나타난다.  
- 사용자가 예측 불가능한 방식으로 애플리케이션을 사용하는 것
- 코드가 환경마다 다르게 동작하는 것

## 운영 준비된 코드 구축

성능 최적화, 환경별 설정, 오류 처리와 로그, 보안 필수사항을 개발 과정 전반에 고려하여 코드가 성공할 최선의 기회를 줄 수 있다.

### 성능 최적화

단지 코드를 더 빠르게 제공하는 문제로도 보일 수 있지만, 궁극적으로는 사용자에게 최상의 경험을 제공하는 것이다.  

성능을 향상하기 위해 활용할 수 있는 핵심 전략
- 비동기 프로그래밍
- 네트워크 호출 경감(한 요청으로 묶어서 보내기)
- 캐시 적용 전략
- 데이터베이스 쿼리 최적화
- 코드 경량화
- 코드 번들링
- lazy loading
- CDN

### 환경별 설정 구성

하드코딩하는 대신, 각 환경에 맞게 설정할 수 있는 구성을 선호하자.

- 로그 설정
- 외부 서비스 종단점
- 데이터베이스 설정
- 캐시 설정
- 이메일 설정
- 보안 설정
- feature flag(release flag, experiment flag, permission flag)와 애플리케이션 동작

### 오류 처리와 로그

적절한 오류 처리와 로그는 단순히 좋은 관행이 아니라 필수적인 생존 기술이다.  
오류 처리로 시스템 전체의 장애로 확산되는 것을 막을 수 있고, 로그는 문제를 해결할 단서를 제공한다.

## 전개 파이프라인

파이프라인은 네 가지 상호 연결된 구성 요소로 이루어진다.  
- 전개 환경(개인 개발 환경, 테스트/QA 환경, 스테이징 환경, 운영 환경)
- 버전 관리 전략(git flow, trunk-based development)
- 전개 자동화(스크립팅)
- CI/CD

## 운영 시스템 모니터링과 유지보수

로그와 지표가 갖춰지면 AI 도구가 모니터링 역량을 강화할 수 있다.  
대량의 로그를 검색하여 패턴을 식별할 수 있고, 대시보드를 생성하는 데 도움을 줄 수 있다.  
처음에는 사소하고 비용이 적은 문제도 크고 비용이 많이 드는 문제로 변할 수 있기 때문에 정기적인 유지보수가 필요하다.
