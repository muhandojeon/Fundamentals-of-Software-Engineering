# 코드 문해력 = 실무 기본 능력

## 인지 편향

- 기존 코드를 다룰 때도 몇 가지 인지 편향이 작용해 우리를 방해한다 
  - 이케아 효과
    - 자신이 직접 만든 것에 더 높은 가치를 부여한다

- 코드를 다루거나 동료 개발자와 협업할 때는 이런 편향을 염두에 둬라
  - 동료가 특정 도구나 방식을 왜 그렇게 고집하는지 잘 모르겠다면, 사견이 껴 있는지 않은지 자문하자. 물론 자신의 가정에 대해서도

## 낯선 코드 접근법

- 문서를 읽어라. 프로젝트 코딩 표준을 만들고 읽어라

> 사용하는 패턴과 도구들을 rules, skill화 해두니 좋았다. use-funnel 같은 경우.

## 테스트에서 얻는 통찰

- 잘 작성된 테스트는 코드가 무엇을 하는지 알려줄 뿐만 아니라 왜 그런 방식으로 작동하는지도 나타낸다

> 그것에 더해. 테스트 비용이 0원에 수렴해진 요즘에 더 중요하고 값어치 있다 생각함.
> 코드보다 readable하기도 하고.
> 그렇지만 좋은 테스트에 대한 지침은 필요하다 생각
