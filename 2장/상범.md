# 2장 코드 문해력 = 실무 기본 능력

인지편향 파트에서 기존 코드를 다룰 때도 몇 가지 인지 편향이 작용해 우리를 방해한다. 이케아 효과라고 하는데, 자신이 직접 만든 것에 더 높은 가치를 부여한다.
> 그래서 코드 리뷰가 꼭 필요한 것 같다. 여담으로 클로드 코드가 자신이 짠 코드에 대해 프라이드를 가져서 스스로 버그를 잘 못잡아낸다고 해서 코드 작성은 클로드 모델, 리뷰는 gpt 모델로 진행하고 있는데 매우 좋습니다

시간들여 문서를 살펴보자. 프로젝트에는 유용한 README 나 위키, ADR 등이 숨어있을지도 모른다. 
> 혹시 ADR, HLD, LLD 이 프로젝트에 있으신 분 계신가요! 있다면 어떻게 관리하는지도 궁금합니다 💭

테스트는 개발자가 새로운 코드를 탐색할 때 또 다른 형태의 문서 같은 역할을 한다. 코드가 기능의 작동 방식을 알려준다면, 테스트는 기능이 어떻게 작동해야 하는지 알려준다.
> 솔직히 아직까지 제대로 테스트를 작성해본적이 없어서 공감하기 어렵네요.. 다들 어떤 코드에 테스트 작성하시고 어떻게 유지보수 하시는지 궁금합니다 👀 그리고 문서 같은 역할을 한다에 공감하시나요?
