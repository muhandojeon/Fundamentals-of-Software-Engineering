# 프로그래머에서 이제는 엔지니어로
* 성공하고 싶다면 다른 사람이 작성한 코드를 읽고 새로운 코드를 빠르게 이해하는 법을 반드시 배워야 한다

## 게으른 프로그래머 정신의 수용

* 게으른 프로그래머 정신은 효율성에 초점을 맞춘 철학이다

* 엔지니어는 본능적으로 해결책을 찾는 데 급급함. 고려할 시간을 갖지 않고 즉시 코드 작성을 시작함 

> 나임 

  + 전략적으로 게으름을 피우는 것은 생각할 시간을 확보해 주며, 이는 궁극적으로 생산성을 높이고 더 나은 해결 방안을 만드는 데 도움이 된다.

## 성급한 해결책 제시의 위험성

* 문제를 마주쳤을 때 너무 빨리 해결책으로 건너뛰려는 충동을 억제해야 한다.
  + 대신 문제의 근본 원인을 이해하는 데 시간을 투자해야 한다

> 나한테 너무 부족한 점.

- 만드는 애플리케이션이 어떤 문제를 해결하는지, 맥락과 제약 조건은 무엇인지, 관련된 문제들은 무엇인지 등 문제 영역을 충분히 생각하는 데 시간을 들이자

> 난이도가 낮은 요구사항들이 팽배한 환경에서는, 클라이언트 개발자에게 도메인 전문성이 요구되지 않는 것 같다 (경험담)

  - 그들과 대화하며 그들의 경험, 배운 점, 더 일찍 배웠으면 하고 바라는 점, 팀에서 더 가치 있는 인재가 된 비결 무엇을 배워야 한다고 생각하는지 등의 이야기를 나눠봐라
