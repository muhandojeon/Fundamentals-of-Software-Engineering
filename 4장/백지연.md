# 4장 소통을 돕는 적정 모델링

이해관계자들에게 기술적 의도를 표현하기 위해 다이어그램을 사용

소프트웨어 모델링 = 소프트웨어 구조, 동작, 기능을 더 잘 이해하고, 분석하고, 소통하기 위해 추상적인 표현을 만드는 과정

**관건은 어떤 다이어그램을 언제 작성해야 하는지 아는 것이다.**

- 컨텍스트 다이어그램
    - 시스템 또는 시스템의 하부 요소 사이의 경계를 정의
    - 프로젝트 초기에 사용
    - 시스템이 무엇을 의미하는지 알 수 있는 큰 그림 제공
- 컴포넌트 다이어그램
    - 동작 중인 시스템의 주요 구성요소를 보여줌
    - 프로젝트가 진행되는 내내 사용
    - 지식 전달 및 온보딩에 유용
- 클래스 다이어그램
    - 클래스들이 서로 어떻게 관련되어 있는지 보여줌
    - 상속 관계뿐만 아니라 구성 관계, 관계의 수(1:1, 1:n, n:n) 포함
    - 모든 클래스를 표현하기엔 너무 방대해서 도메인 경계로 나누어 작성
    - 프로젝트 내내 다듬어짐
    - 신규 및 기존 개발자 모두에게 시스템 전체 범위를 이해하는 데 큰 도움이 될 수 있음
- 순차 다이어그램
    - 상호작용의 순서를 보여줌
    - 특정 흐름과 관련된 개체만 보여줌
    - 프로젝트 기간 내내 사용됨
- 전개 다이어그램
    - 시스템이 동작하는 상황을 시각적으로 보여줌
    - 하드웨어 노드뿐만 아니라 그 위에서 실행되는 소프트웨어를 보여줌
    - 프로젝트 초기에 품질 속성을 검증하는 데 사용
    - 회사에서 사용하는 도구과 기술 세트가 있고, 그것들을 하나로 조립하는 점에서 레고 블록과 비슷
    - 좀 더 전문화된 형태가 보안 다이어그램
- 데이터 모델
    - 여러 데이터 개체와 그 관계를 보여줌
    - 높은 개념 수준에서 구체적인 구현으로 진행됨
    - 프로젝트 초기에 도메인을 설명하려고 만들지만, 프로젝트 수명 주기 동안 계속 다듬어짐

**다이어그램은 독자가 이해하기 쉽게, 단순하게, 템플릿대로 만들어라.**
