# 소통을 돕는 적정 모델링

책에서는 여러 모델링 다이어그램을 설명하고 있지만, 사실 잘 눈에 잘 들어오지는 않았고, 그렇게 주의깊게 읽어보지는 않았다. 
나중에 필요할 때, 사용하면 찾아보고 해당 모델링으로 표현하면 충분할 것

현재 팀에서는 테크스펙을 프로젝트 전에 작성하고 있다. 
책에서 소개하는 다이어그램과는 다르지만, 어떤 작업 순서로 진행할 것이고, 어떤 문제를 어떤 방향으로 풀 지에 대해서 표현하고 사전에 sync 한다는 점에서는 비슷한 방향이지 않을까?

간단하고, 나만 하는 작업이라면 크게 효용이 없을 수 있다.
프로젝트가 복잡해질 수록, 이해 관계자가 많아질 수록, 프로젝트를 가시성 있게 진행하기에 효과적이라고 생각한다.

테크스펙을 리뷰하면서 느낀 점은 결국 중요한 것은 사전에 빠르게 검증하고, 프로젝트가 어떻게 진행될 지 해상도를 높인다는 점이다.

결국 중요한 것은 책에서 소개하는 어떤 다이어그램, 시각화 도구보다 어떤 점이 포함되어야하고, 어떤점을 중요하게 검증해야하는지, 어떻게 최신화를 잘할 수 있을지가 중요하다고 생각하는데, 도구의 소개에서 그쳐서 아쉽다.
검증할 수 있다면, 노션이든, ppt 혹은 claude code design이더라도 조직에 표준화만 되어있다면 중요한 부분은 아니기 때문이다.
