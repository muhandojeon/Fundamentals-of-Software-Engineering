# 4장 소통을 돕는 적정 모델링

개인적으로는 소프트웨어 모델링 정의가 중요하다고 생각한다. 프론트엔드 쪽이라도 회사에서 Next 기반 SSR 서비스를 쓰다 보니, 뒷단의 인프라부터 실제로 유저에게 보여지기까지의 과정을 잘 정의해두는 게 중요하다고 느낀다. AI로 물론 쉽게 작성할 수 있겠지만, 아직은 사람이 가진 컨텍스트를 전부 입력할 수 없는 부분이 있고, 일하는 사람이 가지고 있는 맥락도 있기 때문에 전체 모델을 통째로 AI로 뚝딱 만들기에는 당장은 무리가 있지 않을까 하는 생각이 든다.

## 정리

책에서 말하는 다이어그램은 실제로는 잘 안 쓰는 편이다. 배포 다이어그램 같은 인프라 관련 내용을 위키에 작성할 때 플로우차트로 잠깐 활용하는 정도인 것 같다. 다들 다이어그램을 적극적으로 활용하시는지 궁금하다.
