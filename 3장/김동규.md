# 3장 사람을 위한 코드 작성법

요즘에는 AI가 있다 보니 AI가 작성한 코드를 확인하지 않고 바로 머지되는 경우가 많은 것 같다. 요즘 시대와 맞지 않고 답답하게 느껴질 수도 있겠지만, 나는 AI가 만든 코드도 한 번씩 읽어보는 과정을 고집한다. 결국 AI가 엄청난 생산성을 만들어내는 시대라 해도, 그 코드를 책임지는 건 사람이고 사람이 이해할 수 있어야 한다는 생각이 크다. 특히 작성하는 나뿐만 아니라 코드를 리뷰하는 사람들에게도 어떤 코드를 작성했는지 충분히 이해시키고 가야 한다고 생각한다.

## 바퀴 재발명 금지

비즈니스적인 요구사항에 따라 같은 바퀴라도 어떤 곳은 네모난 바퀴, 어떤 곳은 세모 바퀴를 요구하는 경우가 있다. 바퀴 자체를 재발명하는 건 금지지만, 이렇게 서비스마다 요구사항이 다를 경우 스터디에 참여하시는 분들은 어떤 식으로 해결해 나가시는지 궁금하다.

## 좋은 코드

좋은 코드는 정적 분석 같은 검사도 중요하지만, 결국 코드 리뷰를 통해 팀원끼리 "이런 방향이 좋을 것 같다"를 맞춰 나가는 게 맞지 않을까 생각한다.

## 멋 부린 코드 금지

AI를 통한 결과물이 오히려 이런 코드를 많이 작성하는 것 같다 ㅎㅎ

## 비판받을 용기

팀원 간의 라포가 잘 쌓여 있어야 한다고 생각한다. 누군가를 비판할 용기도 비판을 받을 용기처럼 꽤 노력해야 하는 부분 같다.
