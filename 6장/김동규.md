# 6장 낯선 시스템에 빨리 친숙해지기

## 낯선 코드 이해

지금 회사에 처음 입사했을 때 사가(saga) 패턴으로 구현된 매우 이해하기 힘든 프로젝트를 인수인계 받았는데, 실제로 해당 프로젝트를 만든 사람들은 대부분 퇴사한 상태였다. 이 코드에 대해 설명해줄 사람도 많지 않고 문서도 없는 상황이었는데, 결국 실제로 프로젝트를 진행해보고 특정 이슈, 특히 급박한 이슈가 발생했을 때 직접 해결해본 경험이 오히려 더 집중이 잘 되고 코드를 빠르게 이해할 수 있는 계기가 되었던 것 같다.

## 기존 테스트에 의존하라

앞 장에서 이야기한 내용과 비슷할 수 있는데, 작업하던 프로젝트에 레거시로 남아있던 테스트 코드들이 커버리지를 꽤 높여준 케이스가 있었다. 그런데 문제가 발생했을 때 테스트를 수정하기보다 테스트 자체를 지워버리는 경험을 더 많이 했던 것 같아서 기억에 남는다 (부끄럽지만).

## 정리

책에서 이야기하는 내부 라이브러리 파악 등의 내용은 아마 다들 하고 계실 것 같다. 프로젝트를 빠르게 파악하고 이해하는 본인들만의 꿀팁이 있는지 궁금하다.
